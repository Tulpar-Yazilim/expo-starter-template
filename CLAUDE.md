## Commands

```bash

yarn start:development        # development
yarn start:qa                 # qa
yarn start:staging            # staging
yarn start:production         # production

# Run on device
yarn ios                      # iOS simulator
yarn android                  # Android emulator
yarn web                      # Web browser

# Linting and type checking
yarn lint                     # ESLint
yarn type-check               # TypeScript (tsc --noemit)
yarn lint:translations        # Validate/sort i18n JSON keys
yarn check-all                # All of the above + tests

# Testing
yarn test                     # Run all tests
yarn test:watch               # Watch mode
yarn test --testPathPattern="src/lib/utils"  # Single file/pattern

# Building (EAS)
yarn build:development:ios
yarn build:development:android
yarn build:production:ios
yarn build:production:android

# New packages — always use expo install to get compatible versions
npx expo install <package-name>

# Prebuild native folders
yarn prebuild:development
```

## Environment Setup

The project uses `.env.<environment>` files (`.env.development`, `.env.qa`, `.env.staging`, `.env.production`). These are **not committed**. Required variables are validated by Zod in `env.js` at build/run time.

- **`env.js`** (root) — loads dotenv, validates, and exports `Env` (build-time) and `ClientEnv` (runtime). Import at build level only (used in `app.config.ts`).
- **`src/lib/env.js`** — exposes typed client env variables to the app source. Import via `@env` alias: `import Env from '@env'`.

Never import root `env.js` inside `src/`. Only `@env` / `@/lib/env` is safe in source code.

## Architecture

### Routing (`app/`)

Expo Router file-based routing. The app has two route groups:

- **Public routes** (unauthenticated): `sign-in`, `sign-up`, `forgot-password`, `update-password`, `onboarding`
- **`(app)/`** (authenticated group): `index` (feed), `settings`, `style`
- **`feed/`**: `add-post`, `[id]` (detail)

Authentication gating is handled in layouts — check `app/_layout.tsx` and `app/(app)/_layout.tsx`.

### Source Layout (`src/`)

```
src/
├── api/           # Data fetching: axios client + React Query hooks
│   ├── common/    # client.ts (axios), interceptors, utils
│   └── auth/      # Auth-specific query hooks (use-login, use-sign-up, etc.)
├── components/    # Shared UI
│   └── ui/        # Primitive components: Button, Input, Text, Modal, etc.
├── lib/
│   ├── env.js     # Client env variables (import via @env)
│   ├── hooks/     # Custom hooks (use-theme-config, use-is-first-time, etc.)
│   ├── i18n/      # i18next setup, resources, types, utils
│   ├── providers/ # React context providers (api-provider, auth-provider)
│   ├── stores/    # Zustand stores (auth-store, app-store)
│   ├── storage.tsx # MMKV storage wrapper
│   ├── test-utils.ts # Custom render() for tests
│   └── utils.ts   # Shared utilities (includes createSelectors)
├── translations/  # i18n JSON files (keys must stay sorted — enforced by lint)
└── types/         # Shared TypeScript types
```

### State Management

**Zustand** with MMKV persistence for global state:

- `auth-store.ts` — token state (`signIn`, `signOut`), persisted via MMKV. Access via `useAuth.use.<selector>()` (generated by `createSelectors`).
- `app-store.ts` — app-level state (selected language/theme, first-time flag).

Use `createSelectors` wrapper from `@/lib/utils` when defining stores — it generates per-field selector hooks automatically.

### Data Fetching

Axios client in `src/api/common/client.ts` configured with `Env.API_URL`. React Query hooks live in `src/api/` co-located by domain. Use `npx expo install` to add new dependencies so versions stay SDK-compatible.

### Styling

**NativeWind** (Tailwind for React Native). Use `className` props on components. Colors and fonts come from `tailwind.config.js` — do not use hardcoded values. Import primitive components from `@/components/ui` rather than React Native directly.

Prefer gap/padding on container views over asymmetric margins.

### Internationalization

i18next + react-i18next. Translation keys live in `src/translations/*.json`. JSON keys **must stay sorted** (enforced by `yarn lint:translations`). Access strings via `useTranslation()` hook. Language preference is stored in `app-store`.

## Code Conventions

These are enforced by ESLint and the cursor rules:

- **Files/directories**: kebab-case
- **Exports**: named exports preferred
- **Types over interfaces**; no enums — use `const` objects with `as const`
- **No `any`**; explicit return types on all functions
- **Max 3 function params**, max 70 lines per function, max 120 lines per component
- **No `console.error`** — use proper error boundaries or logging utilities
- **Absolute imports** via `@/...` path alias (maps to `src/`)
- Inline type imports: `import { type Foo } from '...'`
- Pure functions use the `function` keyword; component props defined as a `type` at the top of the file

## Git Workflow

Commit messages follow Conventional Commits (enforced by commitlint):

```
fix: | feat: | perf: | docs: | style: | refactor: | test: | chore:
```

The pre-commit hook blocks direct commits to `main`/`master`, runs `tsc --noemit` and ESLint. The commit-msg hook validates format. Fix hook failures — do not bypass with `--no-verify`.

## Testing Patterns

- Test files: `component-name.test.tsx` co-located with source
- Use `renderWithProviders` from `src/lib/test-utils.ts` instead of bare `render`
- Skip tests for simple display-only components
- Jest preset: `jest-expo`; test environment: `jsdom` for web-adjacent tests
